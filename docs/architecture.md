# Architecture

`src/shell.qml` composes the system adapters and a single persistent `Island` surface. `core/State.js` decides which view is shown; services do not replace windows. Every visible state retargets `SpringGeometry` from the current position and velocity.

| Layer | Responsibility |
| --- | --- |
| `core/Theme.qml`, `Settings.qml` | Fixed design tokens and validated integration settings |
| `core/State.js`, `Controller.qml` | Priorities, panel toggles, OSD lifetime |
| `core/Motion.js`, `SpringGeometry.qml` | Exact damped spring solution driven by Qt's frame clock |
| `services/` | Native media, audio, notifications, polkit, desktop entries, monitor state; backlight adapter |
| `ui/Island.qml`, `views/` | Natural-scale content, rounded clipping, keyboard focus, input mask |
| `ui/TopBar.qml`, `ScreenCorners.qml`, `InverseCorner.qml`, `NotchRegion.qml` | Full-width primary bar, shifted top corners, concave joins and matching input geometry |
| `ui/CapturePool.qml`, `FrozenBackdrop.qml` | Bounded in-memory captures and blur |
| `locker.qml`, `core/LockAuthController.qml` | Independent Wayland session lock and PAM conversation |
| `lib/island_cli.py` | Process boundaries, explicit IPC routing, configuration, visibility rules, session dispatch |

## Motion

The native transparent island window is up to 920 × 620 logical pixels. The silhouette keeps its horizontal center fixed and its top edge directly below the 28 px bar. At rest its height is zero, leaving only the bar's centered clock. Expanding springs width, height, bottom radius, and concave shoulder radius from their current values and velocities. The shoulders use curve-rendered quarter-circle paths; the native input region combines the body with matching circular cutouts. Only the clock area intercepts input at rest, and hidden mode has an empty region. Content is clipped to the panel's square top and rounded bottom corners. Text never scales with the silhouette.

`ScreenChrome` keeps a full-width overlay surface mapped on the primary output, accepting input over its resource readings and right-side controls. Its clipped contents contain the black bar, clock, and both primary top corners. One `SpringValue` translates that whole group from zero to minus the bar height on fullscreen entry, leaving both top corners fully visible at the screen edge; it reverses from the current position and velocity on exit. Keeping the native surface mapped on the overlay layer prevents compositor fades or fullscreen occlusion from replacing the slide. Reduced motion snaps this offset. Island geometry and input regions follow the same offset when explicit panels restore the bar over fullscreen.

The native StatusNotifier tray is collapsed behind a chevron at the start of the right-aligned control group inside the moving bar. A separate Qt Quick popup window contains a scrollable, four-column icon grid with high-DPI icons, keyboard navigation, tooltip popups, and primary/secondary/scroll dispatch. The chevron toggles the grid; Escape or an outside click dismisses it. The empty tray has no hit area, and attention status is reflected on the collapsed chevron. `TrayMenu` reads native DBusMenu entries through `QsMenuOpener` and presents rounded dark Qt Quick popup windows, with grey highlights, separators, icons, checkbox/radio states, disabled actions, and cascading submenus. Qt manages keyboard navigation, popup grabs, outside-click dismissal, and screen-edge placement. The bar temporarily requests keyboard interactivity before opening a popup, releasing it on dismissal. Menu openers are released when their popup closes. The bar's tray input region covers only the chevron; the popup owns its grid's input region; the clock is routed to the island and unused bar space stays click-through. The grid, tray menus and tooltips close as the slide starts.

`SystemStats` adds a separate input region on the left for CPU/RAM/GPU percentages, used space on the root filesystem, and an optional laptop battery. Clicking any metric toggles the ordinary `system` panel through the central controller. `SystemView` shares the island's geometry, focus, clipping, and interruptible morph; notifications queue, OSD stays inline, and authentication preserves it for restoration. Entering fullscreen dismisses this bar-opened panel. The active bar surface participates in the island's Hyprland focus grab so clicking its readings again can close the panel reliably. Ordinary panels request this Wayland grab regardless of whether their launcher inherited `HYPRLAND_INSTANCE_SIGNATURE`; the IPC identity is not required by the focus-grab protocol. Outside clicks dismiss the panel without adding an invisible desktop input surface. Authentication disables this dismissal grab. Ordinary panels bootstrap keyboard focus with `Exclusive`, then switch to `OnDemand` once the grab is active so the grab owns keyboard focus. Keeping layer focus exclusive would force outside pointer hit-testing back onto the island in Hyprland, preventing the grab from clearing. The grab initially contains only the island, then adds the bar after the focus handover commits, preventing keyboard focus from landing on a bar with no text input. Compositors without this protocol retain the original exclusive keyboard behavior; authentication always retains it. Status exposes the requested and active grab states as `outsideClickRequested` and `outsideClickArmed`.

`SystemService` consumes JSON lines from one read-only Python sampler, `lib/telemetry.py`, every two seconds, and keeps only 31 samples. CPU uses deltas of `/proc/stat` without double-counting guest time; RAM uses `MemAvailable`. Temperatures come from CPU/DRM hwmon or CPU thermal zones. AMD counters use sysfs; NVIDIA queries are bounded to 1.2 seconds and back off for 30 seconds on errors. Suspended NVIDIA devices are excluded from queries. Intel's i915/xe fallback deduplicates readable per-user DRM client counters and reports the busiest engine's utilization, normalized by engine capacity. It is session activity, rather than a privileged system-wide GPU measurement. Missing data remains null, not a fabricated zero. The displayed GPU is the busiest supported device; changing GPU identity leaves gaps in its history. UPower supplies the optional system battery, including charge, rate, time estimate and supported health data. The poller stops during locking. Canvases repaint only on new visible data or size changes; there is no graph animation timer.

`AudioService` binds the default PipeWire sink/source continuously and binds other audio nodes while the audio panel is open. Device preferences use native `preferredDefaultAudioSink/Source`; rows reflect confirmed defaults and WirePlumber handles routing. Controls check current node membership/readiness before dispatching, including during removal. Stream groups are built from application identity and direction without reading gain values, so volume updates do not recreate a slider during a drag. Playback and capture groups remain separate. Native audio gain and mute properties update directly; global OSD signals use `volumesChanged` and ignore a 350 ms default-device baseline. Preview suppresses global OSDs, while deliberate controls remain live. The open audio view reflects changes directly instead of adding a duplicate OSD strip for its own volume changes. No peak monitor or capture stream is created.

`AudioView` shares the island surface, interruption rules, keyboard dismissal, and panel priority. The bar groups tray, weather, Bluetooth, network, notifications, audio, and session controls on the right with no extra spacing between their 30 px hit areas. The group has its own input region and joins the existing focus-grab surfaces; unused bar space remains click-through. The session button only toggles the session view. `demo audio` substitutes `DemoAudioBackend`, enables no native trackers, and restores real status after dismissal; authentication preserves the demo for restoration. EasyEffects is discovered through installed desktop entries and opened on explicit activation. Its virtual devices remain selectable; presets and DSP processing stay owned by EasyEffects.

The bar reserves a fixed 28 px outside fullscreen; fullscreen immediately releases that reservation. Each output association is stable and selection enables only the corresponding bar, so reservations move correctly on hotplug. The island ignores exclusion zones, allowing expansion without moving application windows. Separate corner overlays keep the primary bottom corners and all secondary corners stationary. Other outputs have no Island reservation.

The island spring uses angular frequency 32 rad/s and damping ratio 0.72 (about 4% overshoot, settling in under 450 ms), so panels rebound slightly like the Dynamic Island. Screen chrome uses a calm 34 rad/s, 0.85 preset so the bar slide arrives without rebound. Both use an analytical step rather than a frame-rate-dependent Euler integrator. Target changes retain velocity. Subpixel displacement and velocity thresholds stop the frame driver completely after settling. A frame stall is bounded to a 100 ms step. Overshoot below zero while collapsing is clamped in the silhouette. Panel content (`Reveal`) fades in over 200 ms with a 6 px downward settle and leaves in 90 ms; reduced motion snaps geometry and drops the movement. This applies the interruption/continuity guidance from [Emil's animation skill](https://github.com/emilkowalski/skills/blob/main/skills/animate/SKILL.md) to Qt Quick.

## Contention

Locking supersedes all shell UI. Polkit supersedes ordinary panels while preserving their selection and search text. The click-opened media view is an ordinary interactive panel: it persists across pointer movement and media actions, and closes via the clock, Escape, an outside click, or fullscreen entry. Panels supersede OSDs, which are shown inline; standalone OSDs supersede notifications. Fullscreen suppresses passive UI. Notifications queue behind interactive content and expire against their original deadlines. DND, locking, and fullscreen suppress popup delivery without generating a replay burst.

Notifications are copied into plain session-owned records, independent of native object lifetime. Transient records disappear on close. Expired records lose their actions. History is bounded to 200 records; eviction closes any remaining native notification. Replacement property signals are coalesced after the native update. Launch history is a separate, small JSON file.

## Security boundary

The locker does not import the main shell or expose its demo commands. Its only IPC method reports lock status. The native PAM adapter's success signal is the sole path that clears `WlSessionLock.locked`. Tests inject fake PAM objects into the controller from fixtures outside the shipped package; production has no bypass switch.

`lock --wait` waits for the compositor's secure flag. Session suspend dispatch calls that operation before `systemctl suspend`, and aborts if it fails. The shell can disappear or reload without releasing the independent lock. Lock screenshots never use temporary image files; the native test harness deliberately saves screenshots of its synthetic desktop for inspection.

`NetworkService` uses Quickshell.Networking for Wi-Fi and Ethernet devices, scan lifetime, radio state, connection actions, confirmed connection state and native failure signals. Passwords are submitted with `WifiNetwork.connectWithPsk` only for supported PSK security types; saved profiles first use `connect`. Unknown enterprise networks direct users to the existing editor. Pending operations are bounded, device removal invalidates stale targets, and scanner bindings are active only while the network panel is open. The icon-only network entry sits before audio; both have separate input regions. `demo network` injects in-process simulated objects and never dispatches a host network command.

`lib/network.py` supplements native networking with IP/router/DNS and saved VPN metadata through bounded `nmcli` calls, only while the network panel is open. Terse fields parse escaped separators, UUIDs identify profiles, and VPN actions validate the requested UUID against current saved VPNs before argument-array dispatch. Passwords never reach this adapter, logs, CLI arguments, files, or public IPC methods. VPN secret-agent prompts and complex settings remain owned by NetworkManager and the installed editor.

The centered clock toggles `calendar`. `CalendarView` owns a second-resolution SystemClock enabled only while active; the bar retains its minute clock and the hidden view stops ticking. Local civil-date arithmetic uses noon across DST, a Monday-first 42-cell grid, ISO week numbers and keyboard/month navigation. Selected and current dates are displayed separately from the time. No event/account provider is loaded. Media remains an independent panel available through `media toggle`. The island input mask covers only the centered clock within the bar, so a wide expanded body cannot intercept other bar controls, including at fractional scaling.

`BluetoothService` binds native Quickshell.Bluetooth adapter/device objects for confirmed power, connection, pairing/trust and battery state. Adapter selection and device actions validate current membership; device identity remains intact in the sorted view. The bar adds a separate Bluetooth input region before network and audio. `demo bluetooth` substitutes only in-process objects and bypasses the native action process.

`lib/bluetooth_bridge.py` runs while the ordinary Bluetooth panel is open, receives bounded JSON requests on private stdin, and executes BlueZ actions over the system bus with timeouts and readable errors. PIN/passkey responses never cross shell arguments or public IPC. Pair uses the same DBus connection as a lazily registered KeyboardDisplay Agent1, without RequestDefaultAgent. Agent methods validate bluetoothd's unique sender and the explicitly requested device. Numeric comparison and service authorization require explicit approval; pairing never implies persistent trust. BlueZ owns discoverability's 120-second timeout. Discovery sessions are tracked per helper connection, end after 20 seconds or on dismissal/adapter change, and release only Island's own session. Closing/locking cancels pending pairing, stops scans, and unregisters the agent; stdin EOF and SIGTERM follow the same cleanup. The package includes dbus-next in its wrapped Python runtime.

`SystemService.powerProfiles` owns `PowerProfileService`, consumed by a compact `PowerProfileCard` above the system metrics. The card is capability-driven, uses the confirmed active mode, disables unsupported/inhibited requests, and surfaces degradation, application holds and actionable errors. System notch geometry adds room for the selector; the existing Flickable handles short outputs and additional battery/error content. `demo system` isolates profile switching in memory and restores the native provider after dismissal; authentication preserves the demo. Normal bar/CLI system activation uses live profiles.

The pinned native PowerProfiles singleton lacks provider availability/error reporting and updates its selection before write acknowledgment. `lib/power_profiles.py` therefore uses the standard power-profiles-daemon DBus protocol directly for confirmed state and writes, modern `org.freedesktop.UPower.PowerProfiles` first with `net.hadess.PowerProfiles` fallback. One resident helper subscribes to property/name-owner signals with no polling and reconnects to service replacement. It resolves unique owners before writes, revalidates capabilities, requests standard authorization, and reports failure without optimistic selection. Reads/startup never change a mode or acquire a hold. An explicit switch may release other application holds according to daemon policy. The watcher stops during locking; the host owns daemon enablement and hardware policy.

Weather uses an on-demand `WeatherService` and a bounded stdlib HTTPS adapter (`lib/weather.py`) for Open-Meteo forecast/geocoding requests. A single forecast process serializes location/cache writes; revision checks discard superseded results. Debounced searches discard outdated responses. A saved city and a location-matched 15-minute disk cache survive restarts, without IP geolocation or API credentials. Forecast epochs are normalized with the destination's IANA timezone. The view and button use the same state priorities, morph and focus handling as other panels. Demo weather is entirely local.

## Visual design

`core/Theme.qml` holds every colour and size. Surfaces are true black (`#000000`) with barely lifted cards (`#0a0a0a`) and hairline borders; hover and selection are grey only. Indigo (`#6366f1`, Tailwind indigo-500) marks filled active states — switches, slider fills, the active power profile, today's date — and keyboard focus. It is never used for small text. Red (`#f87171`) marks errors and amber (`#fbbf24`) warnings such as low battery, stale forecasts or hot disks. Type is Inter on one scale (11/12/13/15/20/28 px) with tabular figures for numbers. Shared building blocks live in `src/ui`: `Card`, `ViewHeader`, `ActionButton`, `IconButton`, `Toggle`, `Segment`/`SegmentedTrack`, `Input`, `Badge`, `Kbd` and `BarButton`.

Typography uses regular (400) for body copy and metadata, medium (500) for controls and item names, semibold (600) for panel/section headings and main readings, and bold (700) for the selected calendar date. Inter's bundled variable face is registered through `FontLoader`; text primitives and native input/selection controls synchronize the `wght` axis with `font.weight`. Qt can otherwise resolve medium/semibold to the Regular instance when Inter is not installed in system fontconfig, even though `FontInfo.weight` reports the requested weight. The development shell exposes installed Inter instances and can mask this. Synchronization is guarded and imperative because a direct binding between two subproperties of QML's font value produces binding loops. No system font installation or desktop theme changes are required.
